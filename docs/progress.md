# История этапов

## ЛР 1. Старт проекта на React и TypeScript

Создан каркас приложения «Учебный менеджер» на React + TypeScript + Vite в папке `frontend`. Стартовый экран шаблона заменён собственным: название, описание и заглушка раздела «Мои задания». Удалены счётчик, логотипы и иконка Vite. Проект сохранён в едином Git-репозитории.

### Как проверить

1. Выполнить `cd frontend`, `npm ci`, `npm run dev` и открыть адрес из терминала: виден экран «Учебный менеджер».
2. Заменить в `src/App.tsx` значение `appTitle` числом и выполнить `npm run build`: сборка завершается ошибкой типов. Вернуть строку.
3. Выполнить `npm run build`: проверка типов и сборка проходят.
4. Выполнить `npm run preview` и открыть адрес из терминала: виден тот же экран из готовой сборки.
5. Клонировать репозиторий в новую папку и повторить `npm ci` и `npm run build`: проект собирается без переноса файлов.

## ЛР 2. Страницы приложения и навигация

Внедрена декларативная маршрутизация с использованием библиотеки `react-router` (v7), создана модульная структура страниц и компонентов приложения «Учебный менеджер»:

1. **Типизация данных (`src/types/`):**
   - `Course`: интерфейс курса (`id`, `title`, `code`, `description`).
   - `Assignment`: интерфейс учебного задания (`id`, `title`, `description`, `courseId`, `courseTitle`, `dueDate`, `status`, `difficulty`).
   - `AssignmentStatus` (`'todo' | 'in_progress' | 'done'`) и `AssignmentDifficulty` (`'easy' | 'medium' | 'hard'`).
   - Словари понятных русскоязычных названий статусов (`STATUS_LABELS`) и уровней сложности (`DIFFICULTY_LABELS`).
   - Все типы импортируются через `import type` согласно правилу `verbatimModuleSyntax`.

2. **Мок-данные (`src/data/`):**
   - `COURSES`: фиксированный справочник из 5 реалистичных курсов.
   - `ASSIGNMENTS`: список из 7 реалистичных учебных заданий с уникальными идентификаторами, привязкой к курсам, дедлайнами и статусами. Охватывает все категории: выполненные, в процессе, к выполнению и просроченные.

3. **Компоненты и страницы (`src/components/`, `src/pages/`, `src/app/`):**
   - `AppLayout`: единый каркас приложения с заголовком «Учебный менеджер», панелью навигации на базе `NavLink` с индикацией активного маршрута и областью вывода дочерних страниц `<Outlet />`.
   - `AssignmentsPage`: страница со списком заданий, выводом карточек через `AssignmentCard`, плашкой агрегированной статистики по заданиям (всего, выполнено, в процессе, к выполнению, просрочено), обработкой пустого состояния и кнопкой перехода к созданию задания. Поддерживает пропс `assignments` для изоляции тестов.
   - `AssignmentCard`: карточка задания с названием-ссылкой, курсом, бейджами статуса и сложности, дедлайном с проверкой просрочки (бейдж «Просрочено») и ссылкой перехода.
   - `AssignmentDetailsPage`: страница детального просмотра задания по параметру `:id` из `useParams`, отображением всех полей задания, ссылкой возврата к списку, а также корректным экраном «Задание не найдено» при неверном ID. Текст ссылок возврата нормализован (`К списку заданий`).
   - `NewAssignmentPage`: страница создания задания с явной текстовой заглушкой реализации формы в ЛР 3 и ссылкой возврата `К списку заданий`.
   - `NotFoundPage`: страница ошибки 404 для неизвестных маршрутов со ссылкой возврата к списку `К списку заданий`.

4. **Маршрутизация и стили (`src/App.tsx`, `src/App.css`, `src/main.tsx`):**
   - Корневой редирект `<Navigate to="/assignments" replace />`.
   - Маршруты: `/assignments`, `/assignments/new`, `/assignments/:id`, `*`.
   - Обертка `<BrowserRouter>` в `main.tsx`.
   - Современные адаптивные стили (CSS Grid с автозаполнением `minmax(280px, 1fr)`, адаптация для экранов вплоть до 360px, стилизация `focus-visible`, перенос длинных слов через глобальный `overflow-wrap: anywhere`).

### Как проверить

1. Перейти в каталог `frontend` и выполнить `npm run dev`.
2. Открыть в браузере `http://localhost:5173/`: происходит автоматический редирект на `/assignments`, пункт навигации «Задания» выделен активным.
3. Убедиться, что отображается сетка карточек заданий с курсами, цветными бейджами статуса/сложности, дедлайнами и бейджем «Просрочено» для просроченного задания.
4. Нажать на название карточки или ссылку «Подробнее»: открывается `/assignments/:id` с подробными сведениями о выбранном задании и кнопкой возврата.
5. Перейти по адресу несуществующего задания (например, `/assignments/unknown`): отображается заголовок «Задание не найдено» и ссылка «К списку заданий».
6. Нажать в навигации или на странице списка кнопку «Добавить задание»: открывается `/assignments/new` со страницей-заглушкой «Создание задания», сообщением о ЛР 3 и ссылкой «К списку заданий».
7. Ввести в адресную строку несуществующий URL (например, `/something-else`): отображается страница 404 «Страница не найдена» со ссылкой возврата.
8. Проверить целостность данных и бизнес-логику: выполнить `npm test` — все 4 теста успешно проходят.
9. Проверить код линтером: выполнить `npm run lint` — 0 ошибок и 0 предупреждений.
10. Проверить компиляцию и сборку: выполнить `npm run build` — TypeScript и Vite завершают сборку без ошибок.

## ЛР 3. Формы и локальное состояние приложения

Реализован локальный CRUD для сущности «Учебное задание» (`Assignment`), переиспользуемая форма с валидацией, фильтрация по статусу и явное уведомление о хранении данных в оперативной памяти:

1. **Типизация и валидация (`src/types/assignment.ts`):**
   - Тип `AssignmentDraft = Omit<Assignment, 'id'>` для представления создаваемого или редактируемого задания без идентификатора.
   - Константа `EMPTY_ASSIGNMENT_DRAFT` со значениями по умолчанию: пустое название и описание, дефолтный курс из справочника `COURSES[0]`, пустой дедлайн, статус `todo`, сложность `medium`.
   - Функция валидации `validateAssignmentDraft(draft)`: проверка названия (от 3 до 100 символов), обязательного срока сдачи (в формате ГГГГ-ММ-ДД), курса из справочника, диапазона сложности и предметного правила (для статуса `done` обязательно описание не короче 5 символов).

2. **Поднятие состояния и CRUD (`src/App.tsx`):**
   - Состояние `assignments` поднято в корневой компонент `App` с инициализацией копиями из `ASSIGNMENTS`.
   - Функция `createAssignment(draft)`: генерирует стабильный UUID через `crypto.randomUUID()`, неизменяемо добавляет запись в конец массива и возвращает созданный `id`.
   - Функция `updateAssignment(id, draft)`: неизменяемо обновляет запись через `.map()`, сохраняя исходный `id`.
   - Функция `deleteAssignment(id)`: неизменяемо исключает запись через `.filter()`.
   - Прямой импорт `ASSIGNMENTS` исключён из страниц `AssignmentsPage` и `AssignmentDetailsPage`; данные и колбэки передаются через props.
   - Маршрутизация расширена добавлением маршрута `/assignments/:id/edit` с компонентом `EditAssignmentPage`.

3. **Переиспользуемый компонент формы (`src/components/AssignmentForm.tsx`):**
   - Единая форма для создания и редактирования заданий с интерфейсом `AssignmentFormProps` (`initialValues`, `onSave`, `onCancel`).
   - Изолированное локальное состояние черновика (`useState<AssignmentDraft>`), предотвращающее мутацию внешних данных до отправки формы (отмена не затрагивает исходный объект).
   - Управляемые поля ввода: название (input text), курс (select с синхронным заполнением `courseId` и `courseTitle`), дедлайн (input date), статус (select), сложность (select), описание (textarea).
   - Доступность: атрибут `noValidate`, вывод ошибок валидации с `role="alert"`, кнопки с явными типами `type="submit"` и `type="button"`.

4. **Страницы создания и редактирования (`src/pages/`):**
   - `NewAssignmentPage`: отображает `AssignmentForm` со значениями по умолчанию `EMPTY_ASSIGNMENT_DRAFT`. При сохранении вызывает `onCreate` и переходит на страницу созданного задания `/assignments/${id}`. При отмене возвращает к списку.
   - `EditAssignmentPage`: извлекает `:id` через `useParams`, находит задание в общем списке. При отсутствии выводит экран «Задание не найдено». При наличии рендерит форму с атрибутом `key={assignment.id}`, что гарантирует сброс черновика при переходе между записями. Сохранение вызывает `onUpdate` с сохранением прежнего ID.

5. **Просмотр и удаление (`src/pages/AssignmentDetailsPage.tsx`):**
   - Кнопка перехода к редактированию «Редактировать» (`/assignments/:id/edit`).
   - Кнопка «Удалить» с модальным подтверждением `window.confirm(`Удалить задание «${assignment.title}»?`)` и последующим редиректом на `/assignments` (`replace: true`).

6. **Страница списка и фильтрация (`src/pages/AssignmentsPage.tsx`):**
   - Локальный фильтр по статусу задания (`useState<AssignmentStatus | 'all'>('all')`).
   - Подсчет статистики `calculateAssignmentStats` ведётся по полному списку заданий независимо от выбранного фильтра.
   - Разделение двух пустых состояний:
     - Список заданий пуст (`assignments.length === 0`): сообщение «Заданий пока нет.» и кнопка создания первого задания.
     - Фильтр не дал результатов (`visibleAssignments.length === 0` при наличии заданий): сообщение «Нет заданий с выбранным статусом.» и кнопка «Сбросить фильтр».

7. **Уведомление о хранении в памяти (`src/app/AppLayout.tsx`, `src/App.css`):**
   - Информационная плашка в `AppLayout` с пояснением: данные сохраняются временно в оперативной памяти и сбросятся при перезагрузке (F5); постоянное хранилище появится при подключении Supabase.
   - Стили для формы, полей ввода, ошибок, фильтра, кнопок и адаптивной раскладки для мобильных устройств.

8. **Тестирование (`test/integrity.test.ts`):**
   - Добавлены тесты для `EMPTY_ASSIGNMENT_DRAFT`, валидатора `validateAssignmentDraft` (включая предметное правило), неизменяемости операций CRUD и корректности фильтрации по статусам.

### Как проверить

1. Перейти в каталог `frontend` и выполнить `npm run dev`.
2. Открыть в браузере `http://localhost:5173/`: вверху страницы виден баннер с информацией о временном хранении данных в оперативной памяти.
3. Нажать кнопку «Добавить задание»: открывается форма по адресу `/assignments/new`.
4. Попробовать отправить форму с пустым названием или короче 3 символов: выводится сообщение об ошибке с `role="alert"`, данные формы не стираются.
5. Выбрать статус «Выполнено» и оставить описание пустым: валидатор требует подробное описание результата (не менее 5 символов).
6. Заполнить валидные данные (например, название «Новое задание по сетям», курс «Компьютерные сети», дедлайн «2026-11-15», описание «Отчёт по протоколу HTTP/3») и нажать «Сохранить»: происходит автоматический переход на страницу `/assignments/:id` созданного задания.
7. Вернуться в список заданий («К списку заданий»): созданное задание присутствует в сетке, счётчик статистики увеличился.
8. Нажать «Подробнее» у созданного задания и нажать кнопку «Редактировать»: открывается `/assignments/:id/edit`, поля предзаполнены текущими данными.
9. Изменить название или статус, нажать «Отмена»: происходит возврат к просмотру, данные задания не изменились.
10. Снова открыть редактирование, внести изменения и нажать «Сохранить»: изменения сохраняются под прежним `id`.
11. На странице списка воспользоваться фильтром по статусу:
    - Выбрать «Выполнено» — отображаются только выполненные задания.
    - Выбрать статус, для которого нет заданий: отображается экран «Нет заданий с выбранным статусом.» и кнопка «Сбросить фильтр».
    - Нажать «Сбросить фильтр» — восстанавливается полный список.
12. Открыть любое задание и нажать кнопку «Удалить»:
    - В диалоговом окне `confirm` нажать «Отмена» — задание не удаляется.
    - Нажать «Удалить» и подтвердить — происходит возврат к списку заданий, задание удалено.
13. Удалить оставшиеся задания: отображается экран «Заданий пока нет.» и кнопка «Создать задание».
14. Перезагрузить страницу (F5): восстанавливается исходный демонстрационный набор из 7 заданий.
15. Запустить тесты целостности: в папке `frontend` выполнить `npm test` — все тесты успешно пройдены.
16. Проверить линтинг: выполнить `npm run lint` — 0 ошибок и 0 предупреждений.
17. Проверить production-сборку: выполнить `npm run build` — TypeScript и Vite компилируют проект без ошибок.
