# Учебный менеджер

Веб-приложение для ведения личных учебных заданий по фиксированным курсам. Проект выполняется в рамках лабораторного практикума «Практический курс веб-разработки: React, TypeScript, Node и Supabase» (ПГУ им. Т.Г. Шевченко, Физико-технический институт).

**Автор:** Мунтян Артур Олегович, группа 24ПИ1

## Тема и основной сценарий

Учебный менеджер помогает студенту вести личные задания по своим курсам. Пользователь добавляет задание с названием, описанием, курсом, дедлайном, статусом и сложностью, отмечает выполнение, редактирует данные, удаляет ненужные записи и находит задания с помощью фильтра по статусу.

Данные приложения: сущности `assignments` (название, описание, курс, дедлайн, статус, сложность) и `courses` (фиксированный справочник курсов).

## Маршруты и страницы приложения

В рамках ЛР 3 реализована работа с формами и локальным состоянием приложения:

- `/` — автоматическое перенаправление на `/assignments` (`<Navigate to="/assignments" replace />`).
- `/assignments` — страница со списком заданий (`AssignmentsPage`):
  - Отображение карточек заданий через компонент `AssignmentCard`.
  - Сводка статистики (всего, выполнено, в процессе, к выполнению, просрочено).
  - Локальный фильтр по статусу («Все», «К выполнению», «В процессе», «Выполнено») с кнопкой сброса фильтра.
  - Четкое разделение пустых состояний: когда в приложении нет ни одного задания («Заданий пока нет.») и когда под текущий фильтр нет совпадений («Нет заданий с выбранным статусом.»).
  - Кнопка «Добавить задание».
- `/assignments/new` — страница создания нового задания (`NewAssignmentPage`):
  - Переиспользуемая форма `AssignmentForm` с начальными значениями по умолчанию `EMPTY_ASSIGNMENT_DRAFT`.
  - Валидация полей ввода (название от 3 до 100 символов, обязательный дедлайн, обязательное описание не короче 5 символов при статусе «Выполнено»).
  - Кнопка отмены возвращает к списку без сохранения данных.
  - После сохранения происходит переход на страницу созданного задания (`/assignments/:id`).
- `/assignments/:id` — страница детальной информации о задании (`AssignmentDetailsPage`):
  - Вывод названия, курса, описания, срока сдачи, статуса, сложности и бейджа просрочки.
  - Кнопка «Редактировать» с переходом на форму изменения `/assignments/:id/edit`.
  - Кнопка «Удалить» с модальным подтверждением действия через `window.confirm` и возвратом к списку заданий.
  - Экран «Задание не найдено», если передан несуществующий идентификатор.
- `/assignments/:id/edit` — страница редактирования задания (`EditAssignmentPage`):
  - Та же переиспользуемая форма `AssignmentForm` со сбросом черновика по `key={assignment.id}`.
  - Предзаполнение текущими значениями задания, сохранение изменений под тем же идентификатором `id`.
  - Кнопка «Отмена» возвращает на страницу просмотра без внесения изменений.
  - Экран «Задание не найдено» при некорректном `id`.
- `*` — страница 404 (`NotFoundPage`): обработка неизвестных маршрутов с кнопкой возврата к списку заданий.

> **Примечание о хранении данных:** В рамках ЛР 3 все данные хранятся локально в оперативной памяти React-компонента `App` (state lifting) и живут в пределах открытой вкладки браузера. В общем каркасе приложения (`AppLayout`) размещено явное информационное уведомление о том, что при полной перезагрузке страницы (F5) данные сбрасываются к демонстрационному набору ЛР 2. Постоянное хранение в базе данных появится на этапе подключения Supabase.

## Запуск проекта

Из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Адрес сервера разработки выводится в терминале (обычно http://localhost:5173).

## Проверка сборки, тестирования и линтинга

Выполните в папке `frontend`:

```bash
npm run lint
npm test
npm run build
npm run preview
```

## Что работает сейчас

- Полный локальный CRUD для учебных заданий: создание (`createAssignment`), просмотр, редактирование (`updateAssignment`) и удаление (`deleteAssignment`) с сохранением стабильного `id`.
- Неизменяемые обновления состояния: spread-оператор при добавлении, `.map()` при обновлении, `.filter()` при удалении.
- Переиспользуемый компонент формы `AssignmentForm` с контролируемыми полями (`title`, `courseId`, `dueDate`, `status`, `difficulty`, `description`).
- Двусторонняя валидация: обязательные поля, длина названия от 3 до 100 символов, выбор курса из справочника, допустимый статус, сложность в заданном диапазоне, предметное правило (для выполненного задания обязательно подробное описание не короче 5 символов).
- Доступность форм: атрибут `noValidate`, вывод ошибок с `role="alert"`, явные `type="submit"` и `type="button"` у кнопок.
- Локальный фильтр по статусу со сбросом, не затирающий исходный массив записей.
- Разделение двух пустых состояний на странице списка заданий.
- Явное визуальное пояснение о временном хранении данных в памяти в `AppLayout`.
- Покрытие автотестами: проверка схемы мок-данных, типов, правил валидации формы, неизменяемости CRUD-операций и логики фильтрации (`npm test`).
- Полное прохождение линтера oxlint и чистая production-сборка Vite (`tsc -b && vite build`).
