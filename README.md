# Учебный менеджер

Веб-приложение для ведения личных учебных заданий по фиксированным курсам. Проект выполняется в рамках лабораторного практикума «Практический курс веб-разработки: React, TypeScript, Node и Supabase» (ПГУ им. Т.Г. Шевченко, Физико-технический институт).

**Автор:** Мунтян Артур Олегович, группа 24ПИ1

## Тема и основной сценарий

Учебный менеджер помогает студенту вести личные задания по своим курсам. Пользователь добавляет задание с названием, описанием, курсом, дедлайном, статусом и сложностью, отмечает выполнение, редактирует данные, удаляет ненужные записи и находит задания с помощью фильтра по статусу.

Данные приложения: сущности `assignments` (название, описание, курс, дедлайн, статус, сложность) и `courses` (фиксированный справочник курсов в PostgreSQL / Supabase).

## Схема данных и справочник в Supabase (ЛР 5)

Спроектирована схема из 2 таблиц: публичного справочника курсов и личной таблицы заданий с первичными и внешними ключами, предметными ограничениями и разделением прав доступа на уровне PostgreSQL и Row Level Security (RLS).

| Таблица | Назначение | Ключи и связи | Доступ |
| :--- | :--- | :--- | :--- |
| `public.courses` | Публичный справочник учебных курсов | `id text primary key` (PK) | **Публичный (чтение)**: RLS включён; `grant select to anon, authenticated`; политика `"courses are publicly readable"` `using (true)`. Модификация клиентам запрещена. |
| `public.assignments` | Личные задания пользователей (основная сущность) | `id uuid primary key default gen_random_uuid()` (PK)<br>`owner_id uuid references auth.users(id) on delete cascade` (FK)<br>`course_id text references public.courses(id) on update cascade on delete restrict` (FK) | **Закрытый (личные данные)**: RLS включён; права для `anon` и `authenticated` отозваны (`revoke all`). Политики и права отсутствуют до ЛР 6 (клиентский доступ полностью заблокирован). |

### Предметные ограничения схемы (CHECK constraints)

- **`public.courses`**:
  - `courses_id_not_blank`: `check (id = btrim(id) and id <> '')` — идентификатор не может быть пустым или содержать ведущие/хвостовые пробелы.
  - `courses_name_not_blank`: `check (name = btrim(name) and name <> '')` — название курса обязательно, не пустое, уникальное (`unique`).
- **`public.assignments`**:
  - `assignments_title_length`: `check (char_length(btrim(title)) between 3 and 100)` — длина названия от 3 до 100 символов.
  - `assignments_status_allowed`: `check (status in ('todo', 'in_progress', 'done'))` — допустимые статусы задачи.
  - `assignments_difficulty_allowed`: `check (difficulty in ('easy', 'medium', 'hard'))` — допустимые уровни сложности задачи.
  - `description text not null default ''` — описание задания со значением по умолчанию.
  - `due_date date not null` — календарный срок сдачи.
  - `created_at timestamptz not null default now()` — точное время создания записи.

## Переменные окружения

Конфигурация подключения к Supabase осуществляется через переменные окружения с префиксом `VITE_`:

- `VITE_SUPABASE_URL` — HTTPS-адрес вашего проекта Supabase (например, `https://abcdefghijkl.supabase.co`).
- `VITE_SUPABASE_PUBLISHABLE_KEY` — публичный анонимный API-ключ (`anon` / `publishable key`).

Шаблон переменных сохранён в файле `frontend/.env.example`:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_your_key
```

> **Важно по безопасности:**
> - Локальный файл `frontend/.env.local` добавлен в `.gitignore` и **ни при каких условиях не коммитится в Git**.
> - В браузер попадают только публичные переменные с префиксом `VITE_`.
> - Использование секретных ключей (`secret key`, legacy `service_role`) или пароля БД во frontend, коде или репозитории **строго запрещено**.

## Инструкция по развертыванию в Supabase

1. **Создание проекта**:
   - Войдите в личный кабинет [Supabase Dashboard](https://supabase.com/dashboard) и создайте новый проект (например, `course-app`).
   - Задайте надёжный пароль к базе данных и сохраните его в менеджере паролей.
2. **Применение миграции схемы**:
   - В Dashboard откройте раздел **SQL Editor**.
   - Нажмите **New query**, скопируйте содержимое файла `supabase/migrations/202610260001_initial_schema.sql` и нажмите кнопку **Run**.
   - Скрипт создаст таблицы `courses` и `assignments`, настроит ограничения, внешние ключи, включит RLS и назначит политику чтения справочника.
3. **Заполнение справочника (Seed)**:
   - Создайте новый запрос в **SQL Editor**, скопируйте содержимое файла `supabase/seed.sql` и нажмите **Run**.
   - Таблица `public.courses` заполнится 5 начальными курсами с помощью идемпотентного `insert ... on conflict (id) do update set name = excluded.name;`.
4. **Настройка локального окружения**:
   - В Supabase Dashboard откройте **Project Settings** → **API Keys** (или нажмите **Connect**).
   - Скопируйте **Project URL** и **Publishable / Anon Key**.
   - В каталоге `frontend` создайте файл `.env.local` (на основе `.env.example`) и вставьте свои значения:
     ```env
     VITE_SUPABASE_URL=https://<your-project-id>.supabase.co
     VITE_SUPABASE_PUBLISHABLE_KEY=<your-anon-key>
     ```

## Маршруты и страницы приложения

- `/` — автоматическое перенаправление на `/assignments` (`<Navigate to="/assignments" replace />`).
- `/assignments` — страница со списком заданий (`AssignmentsPage`):
  - Отображение карточек заданий через компонент `AssignmentCard`.
  - Сводка статистики (всего, выполнено, в процессе, к выполнению, просрочено).
  - Локальный фильтр по статусу («Все», «К выполнению», «В процессе», «Выполнено») с кнопкой сброса фильтра.
  - Разделение пустых состояний: отсутствие заданий («Заданий пока нет.») и отсутствие совпадений под фильтр («Нет заданий с выбранным статусом.»).
  - Кнопка «Добавить задание».
- `/assignments/new` — страница создания нового задания (`NewAssignmentPage`):
  - Переиспользуемая форма `AssignmentForm` со справочником из Supabase.
  - Кнопка «Обновить справочник» для повторного запроса без перезагрузки страницы и без сброса заполненных полей черновика.
  - Валидация полей ввода (название от 3 до 100 символов, обязательный курс из справочника, срок сдачи, описание не короче 5 символов при статусе «Выполнено»).
  - Кнопка отмены возвращает к списку без сохранения данных.
  - После сохранения происходит переход на страницу созданного задания (`/assignments/:id`).
- `/assignments/:id` — страница детальной информации о задании (`AssignmentDetailsPage`):
  - Просмотр названия, курса, описания, срока сдачи, статуса, сложности и бейджа просрочки.
  - Кнопка «Редактировать» (`/assignments/:id/edit`).
  - Кнопка «Удалить» с модальным подтверждением через `window.confirm`.
  - Экран «Задание не найдено» при неверном идентификаторе.
- `/assignments/:id/edit` — страница редактирования задания (`EditAssignmentPage`):
  - Форма `AssignmentForm` со сбросом черновика по `key={assignment.id}`.
  - Предзаполнение текущими значениями задания, сохранение под тем же `id`.
  - Кнопка «Обновить справочник» для синхронизации курсов с БД.
- `*` — страница 404 (`NotFoundPage`): обработка неизвестных маршрутов со ссылкой возврата.

> **Примечание о хранении данных:** В рамках ЛР 5 постоянным хранилищем становится справочник `courses` в Supabase. Сами учебные задания (`assignments`) остаются в локальном состоянии React-компонента `App` (оперативная память) и возвращаются к демонстрационному набору при перезагрузке (F5). Перенос заданий в PostgreSQL и привязка к `auth.users` (`owner_id`) будут реализованы в ЛР 6 после подключения Supabase Auth.

## Что работает сейчас

- **Справочник курсов в Supabase (ЛР 5):**
  - Воспроизводимая миграция `supabase/migrations/202610260001_initial_schema.sql` со схемой `public.courses` и `public.assignments`, первичными и внешними ключами, предметными ограничениями (CHECK), включённым RLS и политикой публичного чтения справочника.
  - Воспроизводимый seed-файл `supabase/seed.sql` с UPSERT для 5 курсов (`c1`–`c5`).
  - Единый Supabase-клиент `src/lib/supabase.ts` с проверкой наличия `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` (выбрасывает понятную ошибку `Не настроены переменные Supabase в .env.local` при их отсутствии).
  - Сервис `src/services/courses.ts`, запрашивающий курсы через `supabase.from('courses').select('id, name').order('name').abortSignal(signal)`, с обработкой отмены запроса, ошибок доступа/сети и runtime-валидацией через `parseCourses`.
  - Полное удаление старого файла `frontend/public/demo/courses.json` — отсутствие скрытого fallback.
  - Кнопка «Обновить справочник» в форме создания и редактирования заданий: возможность заново запросить данные из БД без перезагрузки вкладки и без потери введённого пользователем черновика.
  - Безопасность: личная таблица `assignments` закрыта от клиентских ролей (`revoke all`, отсутствие политик для `anon`/`authenticated`), секретные ключи отсутствуют в коде и репозитории.
- **Локальный CRUD для учебных заданий (ЛР 3):**
  - Создание (`createAssignment`), просмотр, редактирование (`updateAssignment`) и удаление (`deleteAssignment`) с сохранением стабильного `id`.
  - Неизменяемые обновления состояния: spread-оператор при добавлении, `.map()` при обновлении, `.filter()` при удалении.
  - Переиспользуемый компонент формы `AssignmentForm` с контролируемыми полями и двусторонней валидацией.
  - Локальный фильтр по статусу со сбросом.
  - Разделение двух пустых состояний на странице списка заданий.
- **Автотесты и качество:**
  - Набор из 14 автотестов (`npm test`): валидация структуры курсов, парсинг с контролем дубликатов, проверка SQL-миграции и seed-файла, проверка конфигурации Supabase-клиента и `.env.example`, проверка вызовов сервиса `getCourses` (успех, сортировка, abortSignal, ошибка PostgREST), семантика хука `useCourses`, неизменяемость CRUD, статистика и фильтрация.
  - Полное прохождение линтера oxlint (0 ошибок, 0 предупреждений) и чистая production-сборка Vite (`tsc -b && vite build`).
